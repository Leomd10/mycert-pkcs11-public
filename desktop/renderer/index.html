Conexão com a API

URLs e credenciais da integração.

Informe exatamente a URI cadastrada na aplicação Safeweb. Se ficar vazio, o app monta a URI a partir do "Servidor de callback do MyCert" logo abaixo — não usa mais a demonstração pública (ver DIAGNOSTICO-CALLBACK-SAFEID.md).

Base pública e token do mycert-callback-server (pasta callback-server/ deste projeto). Precisam ser exatamente os mesmos valores usados para subir aquele servidor, e a URI resultante ({servidor}/ca/callback/{token}) precisa estar cadastrada no SafeWeb para este client_id antes de funcionar.

Na demonstração Safeweb, o backend troca o identifierCA por JWT. O Client Secret fica no backend da demonstração; não publique nem compartilhe esse valor.

Necessária na troca do identifierCA por token de sessão: o SafeWeb exige a concatenação de dois fatores (identifierCA + esta senha) no serviço "Autorização com credenciais do titular". Sem ela, a troca é recusada com "segundo fator de autenticação" faltando.

Certificado e token

Dados públicos usados pelo módulo nativo.

Informe aqui os dados públicos do certificado em DER convertido para Base64. A chave privada nunca é armazenada.

chain_der_b64 (opcional, mas recomendado): lista com os certificados intermediários da cadeia (AC emissora e ACs acima dela), também em DER Base64. Sem eles, assinadores reportam "Cadeia de Certificados: AUSENTE". Os certificados da cadeia podem ser baixados no repositório da AC — a URL costuma estar dentro do próprio certificado do titular, na extensão Authority Information Access.
